# Demand Sensing Router v1.2 Benchmark

Date: July 15, 2026

## Audit Verdict

The v1.1 pack had credible operating logic, runnable scripts, a data contract, and planner-reviewable examples. Its entry experience behaved like an eight-page manual, however: each section forced a new page, the official Shetty's Desk mark was absent, large empty areas weakened the perceived value, and a beginner needed several commands before receiving proof that the package worked.

The v1.2 release keeps the deep reference material in Markdown and turns the PDF into a four-page field guide:

1. outcome, three routing lanes, and human decision boundary;
2. one-command sample run, completed example, and tool-path choice;
3. two-file replacement map and non-negotiable evidence contract;
4. review order, troubleshooting, checklist, and next move.

## Benchmark Patterns

| Reference | Pattern adapted | Application in v1.2 |
|---|---|---|
| GitHub Quickstart content model | State audience, prerequisites, outcome, a short task, troubleshooting, and next steps | Five-minute sample run with a visible pass result and exact next files |
| GitHub Hello World | Beginner-safe, result-driven steps with no assumed setup knowledge | One command from the extracted folder and a known-good fixture |
| Anthropic Agent Skills overview | Self-contained instructions, scripts, references, and reusable resources | Skill folder remains portable; START.py verifies the surrounding pack |
| Anthropic Skill authoring best practices | Progressive disclosure, concise entrypoint, validation, concrete examples, clear errors | Four-page entry guide with deeper policy and data contract kept in the skill |
| OpenAI Skills guidance | Reusable and shareable workflow packages with instructions, examples, and code | Portable skill plus chat-first path, sample data, scripts, and outputs |
| IDEO Prototyping Plan | High page economy: purpose and use first, working canvas second | Compact field guide instead of one topic per page |
| Michael Sylver creator playbook | Completed example, inspection logic, reusable framework, and improvement loop | Known-good routing cases, exception-first review, and repeatable checklist |
| Workflows.io LinkedIn playbook | A short, numbered progression that can be scanned quickly | Four numbered pages with one communication job each |

## Quality Standard For Future Packs

- Provide a direct download; no email, account, or newsletter gate unless the user explicitly changes the model.
- Make the first safe run one command where practical.
- Use synthetic data and produce visible success evidence.
- Include a completed example, not only empty templates.
- Keep the entry PDF to four pages by default; move deep reference material to Markdown.
- Use the official Shetty's Desk logo and identity colors, then apply content colors functionally.
- State the required inputs, expected outputs, limitations, and human decision boundary.
- Include version metadata, a machine-readable manifest, deterministic validation, and release notes.
- Begin the operating review with changed rows and exceptions.
- Serve MP4 on the website when an MP4 master exists; retain GIF for LinkedIn publishing.
